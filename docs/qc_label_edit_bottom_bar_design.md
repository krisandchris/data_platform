# 标注修改模式底栏设计

日期：2026-05-18

## 1. 设计结论

如果样本审阅界面只是给标注人员修改标签，那么底栏不需要填写说明，也不承载最终质检裁决。

底栏只保留四个动作按钮：

- `跳过样本`
- `校验修改`
- `保存草稿`
- `提交修改`

底栏职责是“处理当前标签修改任务”，不是“解释投票原因”或“给出通过/驳回裁决”。

## 2. 底栏布局

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 已修改 5 项 · 字段合法 · 草稿已保存 21:38 · config v1                 │
│                                      [跳过样本] [校验修改] [保存草稿] [提交修改] │
└──────────────────────────────────────────────────────────────────────┘
```

布局规则：

- 底栏横跨整个浏览器底部。
- 左侧显示状态摘要。
- 右侧显示四个按钮。
- 不显示说明输入框。
- 不显示 `通过`、`需修改`、`驳回`、`人工精标`。
- `提交修改` 是主按钮。
- `保存草稿` 是次按钮。
- `校验修改` 是显式校验入口，也可在提交前自动执行。
- `跳过样本` 是弱按钮。

## 3. 按钮语义

| 按钮 | 作用 | 是否写入 patch | 是否离开当前样本 |
| --- | --- | --- | --- |
| `跳过样本` | 当前不处理，返回队列或进入下一条 | 否，除非有已保存草稿 | 是 |
| `校验修改` | 只运行字段合法性检查 | 否 | 否 |
| `保存草稿` | 保存当前 `reviewDraft` patch | 是 | 否 |
| `提交修改` | 字段合法性校验通过后保存 patch，并将样本标记为已完成标注修改 | 是 | 可配置，默认进入下一条 |

`校验修改` 的范围必须限制在单字段合法性：

- 字段类型是否合法，例如 string、number、boolean、array。
- 必填字段是否为空。
- closed enum 字段是否命中 active label config。
- open tag 字段是否满足长度、去重、字符安全规则。
- `confidence`、`verification_confidence` 是否在 0-1 范围内。
- `bbox` 是否仍为 0-1000 量化坐标，且 `x1 < x2`、`y1 < y2`。
- 文本字段是否超过长度限制或包含不允许内容。

`校验修改` 不处理以下内容：

- 不判断 Relation 是否真实成立。
- 不判断 Candidate 证据是否充分。
- 不做跨字段业务一致性判断。
- 不做质检通过/驳回裁决。
- 不保存草稿，不提交 patch，不改变样本队列状态。

## 4. 底栏状态摘要

底栏显示紧凑状态摘要：

- `已修改 N 项`
- `未保存` / `草稿已保存 HH:mm`
- `字段合法` / `字段非法 N 项` / `有字段警告 N 项`
- `配置版本 urban_violation_labels_v1`

示例：

```text
已修改 5 项 · 字段合法 · 草稿已保存 21:38 · config v1
```

如果校验失败：

```text
已修改 5 项 · 字段非法 2 项 · 请修正后提交
```

## 5. 提交流程

```text
标注人员修改字段
  -> reviewDraft 产生 dirty fields
  -> buildPatch 生成差异
  -> 校验修改
      -> active label config 存在
      -> closed enum 值合法
      -> open tags 格式合法
      -> bbox 仍为 0-1000 且 x1 < x2, y1 < y2
      -> required fields 不为空
  -> 保存草稿
  -> 提交修改
      -> 保存 patch
      -> 标记样本状态为 annotation_submitted
      -> 写入 audit log
      -> 默认跳到下一条
```

## 6. Patch 字段建议

提交 payload 不使用 `review_decision`，也不要求 `change_note`。

```json
{
  "sample_id": "000142_0_1762483003246",
  "task_mode": "label_edit",
  "label_config_id": "label-config-20260517-001",
  "label_config_version": "urban_violation_labels_v1",
  "operations": [],
  "submit_action": "submit_changes",
  "task_status": "annotation_submitted"
}
```

草稿保存：

```json
{
  "submit_action": "save_draft",
  "task_status": "annotation_draft"
}
```

## 7. 与当前预览稿的调整

`docs/qc_step_review_field_layout_preview.html` 应满足：

- 底栏 aria-label 为 `标注修改底栏`。
- 底栏不显示说明输入框。
- 按钮只包含：`跳过样本`、`校验修改`、`保存草稿`、`提交修改`。
- 状态 chip 显示：`已修改 5 项`、`字段合法`、`草稿已保存`。

## 8. 验收标准

- 底栏不出现说明输入框。
- 底栏不出现质检裁决按钮。
- `校验修改` 只执行字段合法性校验，不做样本级业务裁决。
- `提交修改` 前必须执行字段合法性校验。
- 没有 active label config 时不能提交修改。
- 没有任何 dirty fields 时，`保存草稿` 和 `提交修改` 禁用。
- 提交后状态进入标注修改完成队列，而不是质检通过/驳回队列。
